## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`apps/editor` is the main maintainer UI for curated data and currently reads and writes v7 files. It must edit v8 base records, mods and i18n files while keeping its write-safety guarantees.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The editor reads and writes v8 base records and their i18n text
- [x] #2 The editor can view and edit Champions overrides, or the workflow explicitly limits mods to the Champions tool and documents it
- [x] #3 Writes validate against v8 schemas and preserve sibling records and index order
- [x] #4 `pnpm test:editor`, `pnpm typecheck:editor` and `pnpm test:e2e:editor` pass
- [x] #5 The Dataset editor guide (doc-10) is updated
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Keep the editor's in-memory models with English text; join/split text at the *.server.ts boundary (labels from i18n/eng, searchable Pokémon across locales).
2. Pokédex save: record to pokedexes/ID.json, text to i18n/eng/pokedexes.json (meta entry text preserved); box presets: records to boxpresets/, text to i18n/eng/boxpresets/<variant>/<set>.json; validate both parts before writing; siblings and order untouched.
3. Limit mods to the Champions tool (documented) rather than editing them.
4. Port unit and Playwright tests; update doc-10.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decision (AC2 option): game set mods are not editable in the editor; mods/champions is generated by pnpm champions:update and manual edits would be overwritten. Documented in doc-10.
Availability source comparison now attaches English name/formName before matching forms (needed for Zygarde-10 etc.).
Pre-existing e2e failure: 'source errors can be retried…' expected Zygarde-10 Sword 'unknown', but a curated 10% Forme rule (2026-09-25, after the test) makes it obtainable; verified it also failed on the pre-v8 commit 4c762a12, then updated the assertion. One modern-preset e2e run timed out once in dev and passed on rerun (flaky dialog wait).
Bulk maintenance writes stay structural (schema-migration tool), documented.
<!-- SECTION:NOTES:END -->
